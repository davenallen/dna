description:
  title: Case study
  content: |
    <p><strong>Role:</strong> UI design + front-end</p>
    <p><strong>Context:</strong> An injury page that starts with a choice of path. Each path asks a different short set of questions, one step at a time.</p>
    <h5>The decision</h5>
    <p>A person should pick the kind of injury first, then answer the current question and move on. The contact fields come after the questions. The result stays on the page.</p>
    <h5>What I owned</h5>
    <ul>
      <li>The path selector: vehicle, personal injury, and workers' comp.</li>
      <li>The questions on each path, including the note, ZIP, name, email, and phone.</li>
      <li>The confirmation. Form data is kept for demonstration purposes only and will not be sold or shared.</li>
    </ul>
    <h5>How someone else reuses it</h5>
    <p>A new offer passes a list of paths. Each path is its own list of questions. A choice advances the form. The last step is the result, still on the page.</p>
    <h5 id="react">In React</h5>
    <p>InjuryForm holds the paths and the steps. Choosing a path or an answer records lead_step. Reaching the result records lead_complete. Form data is kept for demonstration purposes only and will not be sold or shared. The same idea of keeping a path in the browser is the <a href="/projects/16-injury-evaluation/">injury evaluation landing page</a>.</p>
